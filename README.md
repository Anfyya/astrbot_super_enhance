# 超级增强（astrbot_plugin_super_enhance）

自用的 AstrBot 增强包：让两个角色（丛雨 `napcat`、亚托莉 `napcat2`）像活人一样过日子、互相知道对方在干什么，
同时把 AstrBot 原生行为里会让聊天"出戏"的地方补掉。配置页按功能分组，每组一个启用开关。

| 分组 | 功能 |
|---|---|
| ① `typing` | NapCat 私聊「对方正在输入」 |
| ② `stay_silent` | 静默工具：AI 可以决定这一轮不说话 |
| ③ `msg_time` | 给 AI 自己的消息盖真实发送时间，并剥掉模型模仿的时间戳 |
| ④ `context_tools` | `/usage`、`/compact`、`/compact v2`，以及上下文超限守卫 |
| ⑤ `cross_session` | 跨会话 / 主动对话发出去的话补进对应会话历史 |
| ⑥ `life_state` | 每日日程、共享场景、能力清单、约定、事件、主动对话、每日回查 |
| ⑦ `reply_guard` | 新消息优先：回复还没发出去时又来了消息，就丢掉上一轮重答 |
| ⑧ `cron_context` | 主动对话（cron）只带最近一段纯对话，省 token |
| ⑨ `sleep_tool` | `sleep_for`：说一句「我去拿一下」，等一会儿再接着说 |
| ⑩ `bot_dialog` | 两个机器人互聊的节奏、跨会话记录、委托回报、`tell` 传话、发消息 / tell 的说明 |
| ⑪ `request_snapshot` | 保存每次真实发给模型的请求（面板「上下文」页查看） |

工具全部照常给模型（懒加载 10/4 撤掉）；长期记忆用 livingmemory 原生的召回和注入（召回过滤 10/4 撤掉）。

另有两处始终生效的底层补丁：**会话历史并发合并**（`history_merge.py`）和**每轮收尾**（`turn_state.py`），见文末。

## 各功能说明

### ① 输入状态（`typing`）

LLM 回复发出前调用 OneBot `set_input_status`，再等 `delay_seconds` 秒。仅私聊、仅 aiocqhttp。
回复另一个机器人时不发（对面 NapCat 会把输入状态推成一条空消息）。

### ② 静默工具（`stay_silent`）

AI 调用后本轮不发任何消息。本轮开始后又来了新消息时，第一次调用会被拒绝（让它先看新消息）。
静默轮还没结束时来的新消息，会从「折叠进当前轮」里摘出来，当作新的一轮正常回答。
静默轮里模型最后写的那句话**不写进历史**（没发出去的话不算说过）；工具调用照常保留。

### ③ 消息时间戳（`msg_time`）

每轮结束给 assistant 消息追加 `<system_reminder>Sent at: …</system_reminder>`；发送前和写历史前剥掉模型
自己模仿的时间戳；系统提示里声明「时间戳由系统生成」。

### ④ 上下文工具（`context_tools`）

- `/usage`：当前上下文占用。
- `/compact`：无损压缩，只丢思考链和工具结果，对话原文不动。
- `/compact v2 [Nd|Nh|Nm] [临时要求]`：前情备忘 + 原话摘录 + 最近原文。先出预览，
  `/compact v2 continue 意见` 微调，`/compact v2 enter` 写入（写前整份备份），`/compact v2 undo` 撤销。
- 超限守卫（`overflow_guard`）：拦掉 AstrBot 的自动压缩；上下文用量超过上限的 82% 时不调模型，
  只发一句固定提醒（`overflow_replies`，每行 `机器人id=句子`），等主人手动 `/compact v2`。
- 报错用角色自己的口吻（`error_replies_model` / `error_replies_review` / `error_replies_cron`，
  每行 `机器人id=句子`，可写多行随机挑）：聊天时模型请求失败（替掉 AstrBot 的「LLM 响应错误」，
  借它的人格自定义报错；人格里自己填了的用人格那句）、每晚日程回查失败、主动消息前裁剪上下文出错（只是没裁好，主动消息照常进行），
  都发她自己的话，不发系统提示；出了什么错只进日志。没配句子的机器人照旧发原来的报错。
  你发指令回的报错不变。

### ⑤ 跨会话上下文修复（`cross_session`）

- AI 用 `send_message_to_user` 给**别的**私聊发消息：把内容作为 assistant 记录补进对方会话历史；
- 主动对话（cron）给**当前**会话发消息：并入本次 cron 用的会话对象，随 cron 收尾一起落库；
  这一轮的思考也存进她发出的第一条消息（和平时聊天一样，面板「上下文」能看能改）。她这一轮决定不发时
  没消息可挂，思考不存。
- 主动消息的思考开头带一行「【主动消息的思考·不发给模型】」：之后平时聊天发请求时，这几段思考换成空，
  不进模型的上下文；平时聊天自己的思考照常发。在面板里把这行标签删掉，那段思考就会重新发给模型。
  只管 OpenAI 兼容的接口（现在用的就是），Anthropic / Gemini 类接口不经过这里。

### ⑥ 动态生活状态（`life_state`）

**每日日程**
- 每天 00:00（本地时区）先用昨天的聊天回查修正昨天的日程，再**一次调用**生成所有角色当天的日程
  （同一条思考链里排，主人不会被同时安排在两个地方；在一起的时段两边起止时间一致，各按自己的视角写）。
- **相处是倾向，不是配额**：两位角色在一起多少按 `pair_level`（多 / 适中 / 少 / 不要求，默认「多」）
  每天随机定一个当天的样子（几乎整天黏在一起 / 大半天在一起 / 各忙各的但常碰面）；和主人一起的时间
  按 `together_min` 大约几段、每天上下浮动。人设、能力清单或附加要求里写了主人这几天不在就不排主人，没写就当他在。
- **和昨天接上**：生成时带上每位角色昨天的概况、作息、收尾那几段（在哪睡下）和天气——起床的地方接着昨晚
  （能力清单里有长期安排的以那边为准），没做完、在等着的事可以接着做，天气从昨天自然变过来；
  最近几天的概况仍只用来防重复。
- **今日变化**（每天随机给的起点）：天气（接着昨天变）、基调（14 种）、3 件可选的小插曲（49 件里抽）、
  每位角色各一个心情（18 种，时段里的 mood 跟着它走）、大约十天一回的意外（16 种，抽到就必须写进去）。
  每天抽到的记在 `daily_seeds.json`，之后避开：插曲 3 天内不重样，基调不连着两天一样，
  意外 30 天内不重样；同一天重新生成也避开上一版抽到的。心情不避（凭性格，可以天天一样、两人一样）。
- 存储：`life_states.json`，按「机器人 + 日期」归档，保留 `retain_days` 天。
- 聊天时发现当天还没有日程（0 点刚过 / 生成失败）：**放到后台补生成，这一轮先不带日程，聊天不等**；
  后台生成失败后 10 分钟内不再由聊天触发重试。
- 生成失败**不会覆盖**当天已有的日程（也不会覆盖被 `/dls delete` 删掉的标记）。
- 注入：每次请求把当前时段（时段、原本打算、穿搭、可选字段）+ 能力清单 + 约定 + 共享场景，
  用 `extra_user_content_parts` 临时附加（不落库）。不在任何时段里（睡眠）就不注入日程部分。
- 命令（管理员）：`/dls show [时段|HH:MM]`、`/dls full [YYYY-MM-DD]`、`/dls regen [附加要求]`、`/dls delete`。
- 工具：`get_full_dynamic_life_state`、`revise_life_state`（只能改自己今天已有的某一段）。
- 面板「每日日程」页：查看、点哪段改哪段、增删时段、改起床 / 睡觉时间、带临时要求重新生成 / 回查、
  查看和恢复旧版（每次改动前自动存一份到 `life_state_revisions/`）。

**每日回查**（`review_enabled`）
只读「起床 ~ 入睡」之间的聊天，只允许小改 `schedule / location / mood`。聊天来源是插件自己的原始消息副本
（`raw_messages/`，只保留今天和昨天，不受压缩影响），只认两种会话：和主人的私聊、和另一个角色的私聊；
另一个角色说的话在提示词里标成她的名字，不会被当成主人说的。

**共享场景**（`scene_enabled`）
- 每个角色自己用 `update_my_scene` 记「此刻在哪、在做什么」（变了才记，旧的自动变成「上一条」）；
- 主人的位置由 `record_master_scene` 记（只记主人亲口说的；机器人互聊和主动对话里不准记），
  或者主人自己 `/site 地点 [在干什么]`、`/site clear`；
  在上下文页面「共享场景」主人卡片上点「锁定」后只能主人自己改（存在 scene_state.json，当场生效）：`record_master_scene` 不暴露给模型，提示里也不再提它；
- 注入里同时给出自己、对方、主人各自的「此刻 / 上一条」；跨天**不重置**，一直有效到被新的一条替换；
- 需要配 `bot_labels`（如 `napcat=丛雨,napcat2=亚托莉`）。

**能力清单 / 约定 / 事件**（`ledger.py`）
- 能力清单（`record_ability`）：后来学会、或长期改变的事，生成和聊天都会注入；
- 约定（`make_promise` / `close_promise`）：日期必须是绝对日期。当天有具体时间的约定会在日程里
  **切出约定那一小段**（默认 1 小时，不超出原来的时段，前后两截保持原样）；以后的约定到那天生成时必须排进去；
  点名的另一个角色也会一起记上，「和谁」按每个角色自己的视角写；
- 事件：生成时出现的多日事件（祭典等），带起止日期，结束后只能当回忆。

**主动对话**（`proactive_enable`）
日程生成或修改后，在 AstrBot cron 里建一次性任务：起床后 3–15 分钟（早安）、睡前 5–20 分钟（晚安）、
当天约定准点，白天再随机挑 `proactive_middle_count` 个时段、在时段开始后 5–25 分钟说（彼此至少隔 30 分钟）。
目标会话取 `proactive_targets` 里属于该机器人的完整 UMO（没有就用 `session_list`）。

到点**先判断再发**（插件接管 cron 执行入口，只管自己排的任务）：
- 这个会话 5 分钟内有人说过话（主人发来、Bot 发出，或另一条主动对话正在生成）→ 顺延到最后一句话 5 分钟之后再看；
  顺延后和同一会话的另一条撞在一起就并成一条（约定 > 晚安 > 早安 > 中段）；
- 提示词到点现场生成：此刻原本的打算、这是早安 / 晚安 / 约定 / 中段哪一种，结合场景说话，
  不纯汇报日程、也不一点不提；觉得这会儿不合适可以不发（约定到点除外）。AstrBot 自带的英文任务说明整段换掉；
- 提示词里不写「你们上一次说话是…」「主人到现在还没回」：请求里带着最近 24 小时的聊天记录
  （每条前面有 `[月-日 时:分]`），主人回没回、隔了多久、要不要提，由模型自己看；
- 请求里同样补注入能力清单、约定、共享场景；日志会记「顺延到…」「并进…」「已发出 / 这次没发」。

### ⑦ 新消息优先（`reply_guard`）

上一轮还没把回复发出去时又来了新消息：停掉上一轮（不发送），把它的用户消息单独补进新一轮请求，
模型看到的是两条各自带时间戳的用户消息。上一轮**没发出去的话不进历史**：
- 还在生成时被停：保存前就标成不入库（连同 AstrBot 的 `Stop output.` / `Output stopped.`）；
- 已经生成完、只差发送时被停：事后从历史里删掉那几句，新一轮请求里也去掉。
指令、通知事件（戳一戳、输入状态）不触发；上一轮已经结束却没有要发的内容（出错、只调了工具）也不触发。

### ⑧ 主动对话上下文裁剪（`cron_context`）

cron 唤醒时把上下文换成最近 `window_hours` 小时内的纯 user / assistant 文本（最多 `max_messages` 条），
不动数据库。

### ⑨ 延迟续说（`sleep_tool`）

`sleep_for(seconds, note)`：先说的那句会立刻发出，等待结束后接着说一两句。受 AstrBot `tool_call_timeout` 限制。
只用于角色自己一个人能做完的小事；要找另一个角色当场说话用 `send_message_to_user`，只是让她知道一件事用 `tell`
（工具说明和等待结束后的提示里都写明了：别人说了什么你不知道，不要替别人编回答）。

### ⑩ 多机器人对话节奏（`bot_dialog`）

- 两个机器人互聊：按来回计数，第 1..N 次注入节奏提示，超过 `max_rounds` 自动静默；主人开口或超过窗口就清零。
  对方 NapCat 推来的空事件 / 通知事件直接丢弃，不计来回、不写记录；
- 每个来回写一条【跨会话记录】到「主人 ↔ 本机器人」的历史（「我上一句」已经记过的不重复写）；
- 委托回报：主人让她去问另一个角色，聊完（或对方迟迟不回）后自动回报主人；
- `tell`：把一句话直接写进另一个角色和主人的会话历史，不发 QQ 消息。
- 发消息 / tell 的说明（`tool_guide.py`）：AstrBot 自带的 `send_message_to_user` 说明只有一句英文，
  没说另一个角色在哪个会话，角色就乱填 session。每次请求（含主动对话）把这两个工具换成只给这一轮用的副本：
  `send_message_to_user` 写明是真发 QQ、用来问问题 / 要对方回话，session 只列能填的几个
  （另一个角色、主人、留空 = 当前会话）；`tell` 写明只是让对方知道、不发 QQ、对方不会马上回。
  角色的 QQ 号在 `bot_accounts`（每行 `平台id=QQ号`），主人号用 `master_ids`。不动 AstrBot 的全局工具。

### ⑪ 真实请求快照（`request_snapshot`）

最低优先级的 `on_llm_request` 上抓取最终请求（人格、注入、工具都装配完），保留最近 20 份。

## 底层补丁（始终生效）

**每轮收尾**（`main.py` 的 `on_agent_done_turn`，优先级最高）：AstrBot 的规则是事件被停止后，同类钩子跑完
当前这一个就不再往下调用，所以作废 / 静默轮次的收尾必须排第一。这里统一标记「agent 已跑完」，
并把没发出去的话标成不入库。

**会话历史并发合并**（`history_merge.py`）：同一会话里两件事同时在跑（聊天、主动对话、委托回报、跨会话记录），
后存的整份覆盖先存的会丢消息。保存时以「这一轮开始时从库里读到的历史」为基准，把期间别人追加或改动的部分保住，
再接上本轮新增的消息。每次写入前还会统一清掉系统噪声：cron 收尾的
`Output your last task result below.` / `[CronJob] …`，以及中断标记 `Stop output.` / `Output stopped.`。

## 已知取舍

- 日程隔离单位是「机器人」不是「用户」：同一个机器人下所有会话共用一份日程（自用够用，发布前要改成按会话）。
- 主动对话依赖 AstrBot 的 cron，宿主机时间 / 时区异常会影响触发时刻。
- 同名工具（`stay_silent`、`get_full_dynamic_life_state`）与旧插件同时启用时 AstrBot 只保留一个，
  启用某组功能前请先停用对应的旧插件。
