# 超级增强（astrbot_plugin_super_enhance）

自用的 AstrBot 增强包：让两个角色（丛雨 `napcat`、亚托莉 `napcat2`）像活人一样过日子，
同时把 AstrBot 原生行为里会让聊天"出戏"的地方补掉。配置页按功能分组，每组一个启用开关。

过日子这块的核心是**世界线**（`life_state` 分组，`world_mode=live`）：三人（丛雨 / 亚托莉 / 主人）
共用一条「已经发生过什么」的时间线，由两个程序维护——

- **记录员**：聊天里发生的事（她去了哪、开始做什么、主人交代了什么）过一会儿自动记进来，
  还能记下规矩（约束）、打算、约定、在练的事；
- **幕间补写**：没人聊天时，把接下来几小时一段一段补上（手上那件快做完时接着写下一件，睡觉也是一段）。

聊天时把【世界线】块注入给角色（她此刻在做什么、做到多少、接下来有什么、主人定的规矩……），
并按早安 / 晚安 / 约定 / 做完一件大事定时主动发消息。世界线按机器人（平台实例）隔离：
每个机器人一条线，同一机器人下所有会话共用。

| 分组 | 功能 |
|---|---|
| ① `typing` | NapCat 私聊「对方正在输入」 |
| ② `stay_silent` | 静默工具：AI 可以决定这一轮不说话 |
| ③ `msg_time` | 给 AI 自己的消息盖真实发送时间，并剥掉模型模仿的时间戳 |
| ④ `context_tools` | `/usage`、`/compact`、`/compact v2`，上下文超限守卫，报错换成角色口吻 |
| ⑤ `cross_session` | 跨会话 / 主动对话发出去的话补进对应会话历史 |
| ⑥ `life_state` | 世界线（记录员 / 幕间补写 / 注入）、主动对话、能力与约定、在练的事、家里的吃的和东西、`start_doing`、`recall`、`look_things` |
| ⑦ `reply_guard` | 新消息优先：回复还没发出去时又来了消息，就丢掉上一轮重答 |
| ⑧ `cron_context` | 主动对话（cron）只带最近一段纯对话，省 token |
| ⑩ `bot_dialog` | 两个机器人互聊的节奏、跨会话记录、委托回报、`tell` 传话、发消息 / tell 的说明 |
| ⑪ `request_snapshot` | 保存每次真实发给模型的请求（面板「上下文」页查看） |

（面板里没有 ⑨：「现在去做」并进了 ⑥——世界线 live 时才给模型 `start_doing`、`recall`、`look_things`。）

工具可见性跟着开关走：关掉的功能不暴露给模型；世界线 live 之后，本插件只给模型
`stay_silent`、`tell`、`start_doing`、`recall`、`look_things` 五个工具（状态改由程序维护，`get_full_dynamic_life_state` /
`revise_life_state` / `update_my_scene` / `record_master_scene` / `record_ability` /
`training` / `make_promise` / `close_promise` 全部收起）。长期记忆用 livingmemory 原生的召回和注入。

`recall`（回想）：注入的【世界线】只有今天最近几段，以前的事她自己翻。先按关键词 / 日期（今天、昨天、10-14）/
时间（下午、15:00-17:00）搜，只列简短的几条、每条带编号（如 `10-15#e40`）；再填编号看那一刻准确的世界线：
那段的分步和结果、前后各一件、同一时候别人在干什么、顺带的事。可见范围和注入一样（别人的按 seen_by 给细节或粗粒度），
能翻多久以前取决于 `world_keep_days`。

`look_things`（看家里的吃的和东西）：`kind=food` 列出家里现有的吃的（编号 w1、w2……、剩多少、放在哪、哪来的、新不新鲜、大约能放到什么时候），`kind=item` 列出吃的以外的东西（编号 p1、p2……、样子、在哪、在谁手上、什么样、归谁；同一种东西有好几件的排在一起，提醒认准编号），都附最近一天没了的；`id` 填编号看那一件从哪来到现在的每一步、用它做了什么。存货（`things.json`）只有记录员写（聊天里说已经发生了的买、收到、做、吃、用、挪、扔、交给谁，第 18 条吃的、第 19 条东西）；补写在世界线每段上标这段动了哪几件（补写第 18 / 20 条），不写进存货。只在要用的时候现算（补写开跑、调 `look_things`、记录员开跑）：做完、没停在半路的段标的那几步算进去，世界线改了下次一算就跟着变；聊天里记的和世界线对不上时以聊天为准；做完满 7 天的段沉进存货（世界线文件到期会清）。编号由程序发、只增不减，条目不删，没了只是最后一步；做出来的菜是新的一件，`from` 写用料编号。剩多少分三种：米面油盐、调料干货、腌菜按克 / 毫升记准数，每一步存用了多少（`used`）或一共 / 清点出多少（`amount`），按先后现算，没写用量的按平常一次的量扣，扣到 0 算用完、快见底标「快用完了」；一盘菜写大概（吃了一半）；按个数的写个数。新鲜度不存，按每一步的放法、切没切、月份 + 当天天气 + 钟点的屋里气温现算。

另有两处始终生效的底层补丁：**会话历史并发合并**（`history_merge.py`）和**每轮收尾**（`turn_state.py`）；
主动消息那一轮的思考只留档、不发给模型（`proactive_think.py`），见文末。

## 各功能说明

### ① 输入状态（`typing`）

LLM 回复发出前调用 OneBot `set_input_status`，再等 `delay_seconds` 秒。仅私聊、仅 aiocqhttp。
回复另一个机器人时不发（对面 NapCat 会把输入状态推成一条空消息）。

### ② 静默工具（`stay_silent`）

AI 调用后本轮不发任何消息。本轮开始后又来了新消息时，第一次调用会被拒绝（让它先看新消息）。
静默轮还没结束时来的新消息，会从「折叠进当前轮」里摘出来，当作新的一轮正常回答。
静默轮里模型最后写的那句话**不写进历史**（没发出去的话不算说过）；工具调用照常保留。

### ③ 消息时间戳（`msg_time`）

每轮结束给 assistant 消息追加 `<system_reminder>Sent at: …</system_reminder>`；发送前和写历史前剥掉模型
自己模仿的时间戳；系统提示里声明「时间戳由系统生成」。

### ④ 上下文工具（`context_tools`）

- `/usage`：当前上下文占用。
- `/compact`：无损压缩，只丢思考链和工具结果，对话原文不动。
- `/compact v2 [Nd|Nh|Nm] [临时要求]`：前情备忘 + 原话摘录 + 最近原文。先出预览，
  `/compact v2 continue 意见` 微调，`/compact v2 enter` 写入（写前整份备份），`/compact v2 undo` 撤销。
- 超限守卫（`overflow_guard`）：拦掉 AstrBot 的自动压缩；上下文用量超过上限的 82% 时不调模型，
  只发一句固定提醒（`overflow_replies`，每行 `机器人id=句子`），等主人手动 `/compact v2`。
- 报错用角色自己的口吻（`error_replies_model` / `error_replies_review` / `error_replies_cron`，
  每行 `机器人id=句子`，可写多行随机挑）：聊天时模型请求失败（替掉 AstrBot 的「LLM 响应错误」，
  借它的人格自定义报错；人格里自己填了的用人格那句）、每晚日程回查失败（旧路径）、主动消息前裁剪上下文出错
  （只是没裁好，主动消息照常进行），都发她自己的话，不发系统提示；出了什么错只进日志。没配句子的机器人照旧发原来的报错。
  你发指令回的报错不变。
- 上面三种报错发出去以后她本来不知道（模型失败那一轮 AstrBot 不存，主人那句也丢了；另外两种是插件直接发的）。
  `error_note_to_history`（默认开）在发完以后补进她的会话历史：一条 assistant（主人收到的那句 + 系统标记写明出了什么错），
  模型失败还补上主人原话。她下一轮就知道刚才出过事。发给主人的不变。

### ⑤ 跨会话上下文修复（`cross_session`）

- AI 用 `send_message_to_user` 给**别的**私聊发消息：把内容作为 assistant 记录补进对方会话历史；
- 主动对话（cron）给**当前**会话发消息：并入本次 cron 用的会话对象，随 cron 收尾一起落库；
  这一轮的思考也存进她发出的第一条消息（和平时聊天一样，面板「上下文」能看能改）。她这一轮决定不发时
  没消息可挂，思考不存。
- 主动消息的思考开头带一行「【主动消息的思考·不发给模型】」：之后平时聊天发请求时，这几段思考换成空，
  不进模型的上下文；平时聊天自己的思考照常发。在面板里把这行标签删掉，那段思考就会重新发给模型。
  只管 OpenAI 兼容的接口（现在用的就是），Anthropic / Gemini 类接口不经过这里。

### ⑥ 动态生活状态（`life_state`）

开关分三层：`world_mode`（off / shadow / live）+ `world_enabled`（幕间补写）+ 各账本开关。

#### 世界线（`world_mode`）

- `off`：世界线完全不跑，走旧的「每日日程」路径；
- `shadow`：记录员和幕间补写照常跑、世界线照常记，但聊天仍用旧日程；
- `live`：聊天注入和主动消息都按世界线来；每日生成、每晚回查、共享场景注入全部停用。

世界线是三人（丛雨 / 亚托莉 / 主人）共用的一条「已经发生过什么」。数据都在插件数据目录：

| 文件 | 内容 |
|---|---|
| `world/YYYY-MM-DD.json` | 当天的条目，按 `world_keep_days` 天保留 |
| `world_state.json` | 规矩（约束）、打算、记录员 / 补写游标、最近错误 |
| `routine.json` | 作息骨架：每人每天的起床 / 入睡时刻（带抖动） |

- 条目两种：
  - `activity`：一段在做的事，有开始、预计结束和进度（做到百分之几）；写了 steps 的还分步，每步有自己的分钟数；
  - `event`：做事当中顺带发生的一件事（只有一个时刻，不打断手上那段）。
- 写入方优先级 `manual`（网页）> `chat`（记录员）> `step`（补写）；同一个人的 activity 不重叠。
- 主人条目只由记录员按他亲口说的记；补写从来不写主人，只让她们在主人身边做自己的事。
- `world_home`（默认「穗织」）是补写的地点锚点；`world_notes` 写故事里的固定事实（一行一条，记录员和补写都照着写）。

#### 记录员（`recorder_quiet_seconds`，默认 90）

某个会话最后一条消息过了静默阈值、还有没处理的，就把这段对话整理进世界线：

- 输入是带完整日期时间和说话人的原文（`raw_log.py` 单独留的副本，只认「和主人的私聊」「和另一个角色的私聊」）；
- 输出（JSON）：
  - **条目**：她开始做什么、去了哪、什么时候做完；
  - **规矩**（约束）：主人说出口的、往后一直管着她的话（不许做什么 / 往后都要怎么做），带到期条件；
  - **打算**：待会儿要去做的一件具体的事，可以同时有多条（带编号，只增不减，撤掉的编号不再用）；
    新记的打算带了时间段（不超过 3 小时，比如「11:25~12:00」），她那段时间里补写排好的事让开：没开始的撤掉、跨进来的截到打算开始；
    对方写着和她一起的那几段也一样，补写看到空档就把打算排进去（顺带上对方）。同一条打算再记一次不动。
  - **约定**、**在练的事**、**能力**（很少用）；
  - **撤**：`lift_constraints`（规矩到期 / 被撤销 / 对不上了）、`drop_intentions`（打算做完或对不上了）；
  - **说早了**（`early`）：她把后面排着的事说成已经做了 → 主动叫她「改口」；
  - **对不上**（`stale`）：对话让某几段排好的事对不上了 → 没开始的撤掉、正在做的到此为止，交给补写重排。
- 失败时游标不前进，错误写进 `world_state.json`，下次重试。

#### 幕间补写（`world_enabled`）

- 手上那段快做完时（提前 `step_lead_minutes` 分钟，默认 5）接着写下一段；断了（重启、出错）从断的地方往后补，
  最多往回补 `step_window_hours` 小时（默认 3）。一次最多往后写 2 小时（睡觉那段不受限）。
- 要写在一起的几位在同一次调用里写（在一起的时段两边起止和共同的事一致）；程序校验首尾相接、不重叠。
- 每段写：做什么（一句话）、分步（每步在干什么 + 几分钟）、做完的结果、重要程度（1–5）、
  在不在宿舍（`at_home`）、是不是正在吃饭（`meal`），以及粗粒度（`public`）和细节（`doing`）两层。
- **闲着**：没有要做的事就写一段闲着（一段最长 1 小时），照当天抽的「闲着的样子」写；
  拿起「手边的消遣」（能沉浸半天的爱好）不算闲着，做到一半可以回头接着做。
- **睡觉**是一段：从入睡时刻一直写到第二天起床，睡前那段在入睡时刻结束。
- 每段写 `state` 三选一：做事 / 闲着 / 睡觉（存成 `idle`、`sleep`）。程序只认这个字段：闲着最长 1 小时、睡觉一直到起床；
  老条目和记录员、网页写的没有这个字段，才按 doing 里的「睡」「就寝」「歇下」认睡觉。
- **溯源**（`origin`）：每段还写 `from`——照抽到的哪一条（抄原文）、打算 / 约定 / 规矩 / 在练 / 作息、
  「接着：」前面的哪件事，或「自己想的」。程序对照当天抽到的核一遍再存：认出来的记成插曲 / 消遣 / 闲着的样子等，
  说是抽到的却对不上的记成「对不上」并留原话；填了打算编号、在练编号的直接算打算、在练。网页世界线每段显示「来源」。

#### 每日维护（0 点）

清掉超过 `world_keep_days` 天的旧条目、结算在练的事（够数那一刻就算练成）、抽当天随机起点、
复核规矩（到期 / 被撤销 / 对不上的自动解除）、排当天的早安 / 晚安 / 约定。

#### 每天的随机起点（`variety`）

每天 0 点抽一份 `daily_seeds.json`：天气（接着昨天变）、基调（14 种，不连着两天一样）、
每人白天 4 件 / 晚上 2 件**小插曲**、两人一起 1 件、每人 4 样**手边的消遣**、
每人白天 3 条 / 晚上 2 条**闲着的样子**、每人一个**心情**、偶尔一次**意外**（30 天内不重样）。

- **插曲**是「今天发生了一件事」：有新鲜感、有结果，重复了扎眼。
- **消遣**是闲下来顺手做的习惯：随时能停、停了能接，能做很久，天天做也不怪。
- **闲着的样子**只写人在哪、怎么待着，不带道具（免得模型自己编「在火盆边歇着」再顺手添炭）。
- 抽的时候按**冷却**打折：同一个人抽到过的，插曲隔 1 天 ×0.03、2 天 ×0.1、3 天 ×0.25、
  4 天 ×0.45、5 天 ×0.65、6 天 ×0.85、7 天回到 ×1，再往后最多 ×1.3（越久没抽到越容易）；
  消遣轻得多（隔 1 天 ×0.3、2 天 ×0.6、3 天 ×0.85、4 天回到 ×1）。
- 说的是同一回事的几条填同一个**组**（旧物、修东西、唱歌……）：冷却一起算，换个说法绕不过去。
- 池子和权重在面板「插曲与消遣」页看和改：每条一根长条（灰色是初始权重、彩色是乘了冷却的现在权重），
  右边是「明天抽中」的机会（照真实抽法模拟出来的）；内容、各人权重（0 是不给她）、组都能改，
  改过的存 `pools.json`，从下一次抽起生效。

#### 注入（每次请求）

live 时每次请求（普通聊天和主动对话）都注入【世界线】块：

- **你现在**：覆盖此刻的那段事 + 做到百分之几（分了步的只给到正在做的那步）；
- **接下来（还没做）**：往后 90 分钟、最多 3 件——只给事名和先后，不给钟点，也不给结局
  （免得她像报日程表，也免得把后面的事说成已经做了）；
- **你今天**：最近 `world_inject_recent` 条（默认 12）带日期和时间的条目；
- **对方 / 主人**：另一位角色和主人此刻在哪、在做什么；
- **你说过的打算**、**主人定的规矩**，以及【约定】【后来学会的】【在练的事】几块。

注入方式 `injection_mode` 可选 `extra_user_content_parts`（默认）或 `fake_tool_call`；都不落库。

#### 主动对话（`proactive_enable`）

live 时排这几种（AstrBot cron 一次性任务，重启不会重复排）：

- **固定排**：早安（起床后几分钟）、晚安（睡前几分钟）、当天有钟点的约定（准点）；
- **现场排**：出门 / 到家 / 开饭那一刻；做完一件够分（`proactive_done_min_importance`）的事；
  她说早了（改口）；练成一件事；一条打算做完；`start_doing` 接下的事做完。

到点**先判断再发**（插件接管 cron 执行入口，只管自己排的任务）：

- 这个会话 5 分钟内有人说过话 → 顺延到最后一句话 5 分钟之后再看；顺延后和同一会话的另一条撞在一起就并成一条
  （约定 > 晚安 > 早安 > 中段）；
- 出门 / 到家 / 开饭 / 做完一件事只在那几分钟有意义：原定时刻过了 10 分钟还没发出去就不发了；
- 发不发、怎么接话由模型自己判断（约定、改口、练成、打算做完这些必须发）；
- 提示词到点现场生成，不纯汇报状态、也不一点不提；AstrBot 自带的英文任务说明整段换掉；
- 提示词里不写「你们上一次说话是…」「主人到现在还没回」：请求里带着最近 24 小时带时间的聊天记录，
  回没回、隔了多久由模型自己看；
- 请求里同样注入世界线；日志会记「顺延到…」「并进…」「已发出 / 这次没发」。

#### 在练的事 / 能力清单 / 约定（`ledger.py`）

- **在练的事**（`trainings.json`）：要练多久开练时定好；练了多久按世界线里标了这件事的时段累计
  （够数那一刻就算练成）；练成自动写进能力清单，并主动叫她来报一次。
- **能力清单**（`abilities.json`）：后来学会、或长期改变的事；普通聊天和主动对话都会注入。
- **约定**（`promises.json`）：哪天、几点、做什么、跟谁；当天有钟点的会排进世界线并在到点主动提一句，
  以后的到那天轮到；点名的另一个角色那边同时记上。注入接下来 7 天。
- **规矩**（约束）存在 `world_state.json`：记录员记、记录员撤，0 点还会复核一遍。

#### 命令与页面

- 面板「上下文」页：
  - **世界线**：按人看条目 / 规矩 / 打算 / 作息骨架，能增删改（改过的算手动，撞上的补写段让开）；
    还能手动跑一次记录员 / 幕间补写 / 规矩复核；
  - **能力与约定**、**插曲与消遣**（池子编辑）、上下文查看编辑、请求快照；
- `/dls show|full|regen|delete`：旧日程命令（`world_mode=off/shadow` 时用）；live 后查看和改动都在世界线页；
- `/site …`：旧共享场景命令，live 后不再注入；主人的行踪由记录员按主人亲口说的记进世界线
  （也可以在世界线页直接改主人的条目）。

### ⑦ 新消息优先（`reply_guard`）

上一轮还没把回复发出去时又来了新消息：停掉上一轮（不发送），把它的用户消息单独补进新一轮请求，
模型看到的是两条各自带时间戳的用户消息。上一轮**没发出去的话不进历史**：
- 还在生成时被停：保存前就标成不入库（连同 AstrBot 的 `Stop output.` / `Output stopped.`）；
- 已经生成完、只差发送时被停：事后从历史里删掉那几句，新一轮请求里也去掉。
指令、通知事件（戳一戳、输入状态）不触发；上一轮已经结束却没有要发的内容（出错、只调了工具）也不触发。

### ⑧ 主动对话上下文裁剪（`cron_context`）

cron 唤醒时把上下文换成最近 `window_hours` 小时内的纯 user / assistant 文本（最多 `max_messages` 条），
不动数据库。

### ⑩ 多机器人对话节奏（`bot_dialog`）

- 两个机器人互聊：按来回计数，第 1..N 次注入节奏提示，超过 `max_rounds` 自动静默；主人开口或超过窗口就清零。
  对方 NapCat 推来的空事件 / 通知事件直接丢弃，不计来回、不写记录；
- 每个来回写一条【跨会话记录】到「主人 ↔ 本机器人」的历史（「我上一句」已经记过的不重复写）；
- 委托回报：主人让她去问另一个角色，聊完（或对方迟迟不回）后自动回报主人；
- `tell`：把一句话直接写进另一个角色和主人的会话历史，不发 QQ 消息。
- 发消息 / tell 的说明（`tool_guide.py`）：AstrBot 自带的 `send_message_to_user` 说明只有一句英文，
  没说另一个角色在哪个会话，角色就乱填 session。每次请求（含主动对话）把这两个工具换成只给这一轮用的副本：
  `send_message_to_user` 写明是真发 QQ、用来问问题 / 要对方回话，session 只列能填的几个
  （另一个角色、主人、留空 = 当前会话）；`tell` 写明只是让对方知道、不发 QQ、对方不会马上回。
  角色的 QQ 号在 `bot_accounts`（每行 `平台id=QQ号`），主人号用 `master_ids`。不动 AstrBot 的全局工具。

### ⑪ 真实请求快照（`request_snapshot`）

最低优先级的 `on_llm_request` 上抓取最终请求（人格、注入、工具都装配完），保留最近 20 份。

## 底层补丁（始终生效）

**每轮收尾**（`main.py` 的 `on_agent_done_turn`，优先级最高）：AstrBot 的规则是事件被停止后，同类钩子跑完
当前这一个就不再往下调用，所以作废 / 静默轮次的收尾必须排第一。这里统一标记「agent 已跑完」，
并把没发出去的话标成不入库。

**会话历史并发合并**（`history_merge.py`）：同一会话里两件事同时在跑（聊天、主动对话、委托回报、跨会话记录），
后存的整份覆盖先存的会丢消息。保存时以「这一轮开始时从库里读到的历史」为基准，把期间别人追加或改动的部分保住，
再接上本轮新增的消息。每次写入前还会统一清掉系统噪声：cron 收尾的
`Output your last task result below.` / `[CronJob] …`，以及中断标记 `Stop output.` / `Output stopped.`。

**主动消息的思考不发给模型**（`proactive_think.py`）：主动消息那一轮存下来的思考带一行
「【主动消息的思考·不发给模型】」，之后平时聊天发请求时这几段思考换成空；在面板里把那行标签删掉，
那段思考就会重新发给模型。

## 已知取舍

- 世界线按机器人（平台实例）隔离：同一个机器人下所有会话共用一条线（自用够用，发布前要改成按会话）。
- 记录员和幕间补写都是后台模型调用，会花 token；想省就把 `world_enabled` 关掉，只留记录员按聊天记。
- 主动对话依赖 AstrBot 的 cron，宿主机时间 / 时区异常会影响触发时刻。
- 同名工具（`stay_silent`）与旧插件同时启用时 AstrBot 只保留一个，启用某组功能前请先停用对应的旧插件
  （`astrbot_plugin_napcat_typing` / `astrbot_plugin_stay_silent` / `astrbot_plugin_msg_time` /
  `astrbot_plugin_context_tools` / `astrbot_plugin_proactive_context_fix` / `astrbot_plugin_dynamic_life_state`）。
